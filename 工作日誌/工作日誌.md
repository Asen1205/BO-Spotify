1. 專題概述（Project Overview）
本專題旨在建立一套音樂搜尋與推薦系統，主要分為三個階段：
1. 資料庫建置： 使用 Million Song Dataset、使用者音樂聆聽紀錄及 Spotify 音訊資料，建立 PostgreSQL 資料庫。
2. API 開發： 使用 FastAPI 建立音樂搜尋與推薦服務。
3. 使用者介面： 使用 Streamlit 建立操作介面，並透過 API 取得資料。
使用工具： Windows、VS Code、Git、Python 3.13（搭配 uv）、PostgreSQL 17、pandas、SQLAlchemy、psycopg2、FastAPI、uvicorn、Streamlit、requests。

資料集： Kaggle 上的「Million Song Dataset + Spotify + Last.fm」，包含兩個檔案：
- Music Info.csv（約 15 MB）：包含歌曲基本資訊及 Spotify 音訊特徵。
- User Listening History.csv（約 602 MB）：包含使用者與歌曲之間的播放次數紀錄。

4. 第四章：資料庫、聆聽紀錄與 Spotify 資料表
實作內容
- 設計兩個資料表：
  - tracks：包含歌曲 ID、歌曲名稱、歌手、標籤、音樂類型、年份、歌曲長度，以及 9 項 Spotify 音訊特徵，例如舞蹈性（danceability）、能量（energy）及節奏速度（tempo）。
  - listening_history：包含歌曲 ID、使用者 ID 及播放次數。
- 撰寫 ch4_database/schema.sql 及 ch4_database/load_data.py。
- 程式首先讀取歌曲資料，刪除重複的歌曲 ID，再使用 PostgreSQL 的 COPY 指令大量匯入資料。
- 接著以每批 200,000 筆資料的方式讀取 602 MB 的聆聽紀錄檔案，只保留已存在於 tracks 資料表中的歌曲紀錄，刪除缺少必要數值的資料，再匯入資料庫。
- 在 user_id 和 track_id 欄位建立索引，以提升資料查詢速度。

5. 第五章：音樂搜尋與推薦 API（FastAPI）
我在 ch5_api/main.py 中建立以下 API 端點：
- /search：支援不區分大小寫的部分文字搜尋，可依歌曲名稱或歌手名稱搜尋。
- /tracks/{track_id}：查詢單首歌曲的詳細資訊。
- /popular：顯示整體播放次數最高的歌曲。
- /users/{user_id}/history：查詢特定使用者播放次數最多的歌曲。
- /recommend/similar/{track_id}：使用內容式推薦（Content-Based Recommendation）。將每首歌曲的 9 項標準化音訊特徵轉換成向量，再透過餘弦相似度（Cosine Similarity）進行排序，找出相似歌曲。
- /recommend/user/{user_id}：使用協同過濾（Collaborative Filtering）。首先找出與目標使用者聆聽相同歌曲最多的 50 位使用者，再從這些使用者播放過、但目標使用者尚未播放的歌曲中，依照重疊程度及播放次數進行推薦排序。
測試方式：

我透過 FastAPI 自動產生的 /docs 互動式文件頁面測試所有 API 端點，例如搜尋歌曲「Creep」及查詢相似歌曲推薦結果。

我使用 Streamlit 建立 ch6_ui/app.py，並設計三個主要功能分頁：
1. 音樂搜尋與推薦： 搜尋歌曲，並顯示相似歌曲推薦結果。

使用者介面僅透過 HTTP 請求與 API 溝通，使資料庫、API 及使用者介面保持獨立，讓整體系統架構更加清楚。
7. 遇到的問題及解決方法（Problems Encountered and Solutions）
問題一：PostgreSQL 下載失敗（錯誤 0x80190193，HTTP 403）

使用 winget install PostgreSQL.PostgreSQL.16 安裝時，385 MB 的安裝檔下載到一半便中斷，連續失敗兩次。

解決方法： 我先確認電腦沒有成功安裝 PostgreSQL，接著直接從 postgresql.org 官方網站使用瀏覽器下載安裝檔，並手動執行安裝，最後成功安裝 PostgreSQL 17。

問題二：系統無法辨識 psql 和 uv 指令

在 PowerShell 中執行指令時，系統顯示找不到對應的指令。

解決方法：
- uv：當時尚未完成安裝，因此使用 winget install astral-sh.uv 安裝，並重新啟動 VS Code。
- psql：由於 PostgreSQL 安裝在自訂路徑 D:\PortgreSQL\17\bin，而非預設路徑，因此我先搜尋 psql.exe 找出實際位置，再將該資料夾加入 PATH 環境變數，讓系統能夠辨識此指令。[確認是否已永久設定 PATH]
問題三：輸入錯誤指令 uv innit

一開始不小心將 init 拼成 innit，導致專案初始化及套件安裝沒有成功，後續執行程式時也出現 ModuleNotFoundError，顯示找不到 pandas 套件。

解決方法： 重新執行正確的 uv init 及 uv add ... 指令，完成專案初始化與套件安裝後，問題便獲得解決。

問題四：PostgreSQL 密碼驗證失敗

執行 API 時，程式出現 password authentication failed for user "postgres"，導致 API 無法正常啟動。

解決方法： 我查看錯誤訊息（Traceback）的最後一行，發現自己將 DB_PASSWORD 設定為教學文件中的預設佔位文字，而不是真正的資料庫密碼。重新設定正確密碼後，問題便獲得解決。

此外，我使用環境變數讀取資料庫密碼，避免將密碼直接寫入程式碼或提交至 Git。

問題五：瀏覽器顯示 {"detail":"Not Found"}

當我開啟 http://127.0.0.1:8000 時，瀏覽器顯示找不到頁面。

解決方法： 經過檢查後，我發現 FastAPI 並沒有在根目錄（Root Path）設定首頁，因此這並不代表伺服器發生錯誤。正確的互動式 API 文件網址為 /docs。

問題六：Streamlit 顯示「Cannot reach the API」

一開始我在同一個終端機視窗中執行 uvicorn 和 Streamlit，導致其中一個服務停止運作。

解決方法： 我將 API 與使用者介面分別放在兩個獨立的終端機視窗中執行，讓兩個服務能夠同時運作，之後使用者介面便能正常連接 API。

問題七：Git 指令執行錯誤

使用 git add. 時，因為少打一個空格而導致指令錯誤。另外，由於尚未執行 git init，因此出現 fatal: not a git repository 錯誤。

解決方法： 改用正確的 git add . 指令，並先執行 git init 初始化 Git 專案。此外，我將 data/ 及 .venv/ 加入 .gitignore，避免將約 600 MB 的 CSV 資料檔及虛擬環境檔案提交至 Git。[依照實際情況更新]
8. 如何執行專題系統（How to Run the Project）
1. 確認 PostgreSQL 資料庫服務已經啟動。
2. 開啟第一個終端機，設定資料庫密碼並啟動 API：
   $env:DB_PASSWORD = "<password>"
   uv run uvicorn ch5_api.main:app --reload
3. 開啟第二個終端機，啟動 Streamlit 使用者介面：
   uv run streamlit run ch6_ui/app.py
4. 開啟以下網址使用系統：
   - API 文件：http://127.0.0.1:8000/docs
   - 使用者介面：http://localhost:8501
